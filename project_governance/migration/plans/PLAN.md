# ClothScout 独立目录迁移计划

目标：迁往用户指定的 `D:\clothscout`。先复制、重构路径和验证，保留原目录，不删除旧文件。自定义目录不改变运行工具的权限策略。

本次只迁移服装 Agent 的功能代码、相关业务规则/研究资料、数据快照、运行与验收记录、相关 1688 Skill 源码。旧工作区内 paimon_model、开发者入驻网站、npm/构建缓存不是当前 Agent 运行依赖，保留原处并写入排除清单；不复制密钥到普通项目文件。

根目录只含核心模块目录；代码、资料、配置均进入各独立子模块，再按 src/config/docs/records/tests/scripts/vendor 分类。核心模块如下：

```
D:\clothscout\
  project_governance\     项目状态、业务规则、入口、迁移与恢复
  data_acquisition\       Apify读取、TikTok目录、FastMoss、趋势资料
  evidence_processing\    去重、规范化、服装上下文
  demand_discovery\       痛点规则、分类、需求卡、分析串联
  product_sourcing\       查询规划、1688适配、结果解析、独立Skill副本
  product_matching\       SKU对照与供货判定
  human_review\           复核队列
  report_delivery\        报告渲染
  workflow_execution\     配置、CLI、启动、执行流水线、历史运行
  quality_assurance\      回归、记录核验、交付验收
  runtime_support\        项目路径、JSON、时间、标识、异常、Python环境
```

实施顺序：

1. 盘点源文件；创建字节一致的 ZIP 备份与 SHA-256 清单，记录每个文件的新去向。
2. 将历史资料按所属模块搬入新副本；原始 JSON、图片和运行快照不改写。历史代码保留在恢复备份中，不作为现行规则重复索引。
3. 按职责拆分原 analysis/providers/matching/pipeline，保留函数逻辑；用模块导入替换旧耦合。另保留原始源码于备份，可逐文件恢复。
4. 所有活跃路径由新根目录计算，默认数据、Skill、配置、输出、测试不再指向旧工作区；凭据沿用 Windows 用户安全存储。重新创建项目 Python 环境，不生搬旧 venv 启动器。
5. 新项目默认运行和旧快照重放；原 22 项测试保持，并新增迁移路径/目录/档案校验。验证运行无需启动新采集或新找货。
6. 独立审查修改后的路径、模块导入、快照重放和文件清单；修复后重验。
7. 保存 MODULE_INDEX 和索引范围：只索引现行规则/代码，排除恢复备份、原始历史、运行产物和环境；这只是范围配置，不假称已实现向量索引。
8. 新状态为唯一活动入口；旧接续文档改为指向新位置的指针，旧数据和功能文件保留为迁移前备份。

验收：源文件全量进入备份且哈希一致；所有源文件有分类或明确保留位置；根目录无散落文件；独立模块各有文件夹；新进程从新目录启动且不依赖旧工作区路径；测试、离线运行、历史重放通过；API/采购外部凭据未输出；缺失或未验证项如实记录。
